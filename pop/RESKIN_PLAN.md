# RESKIN_PLAN.md — ポップ版「ほしめぐり」への置換計画

現行版（リポジトリ直下）は一切変更しない。作業は `pop/` の中だけ。

- **テーマ**: B案「ほしめぐり」（夜空をわたる観測船。承認済み）
- **アプリ化**: Capacitor（承認済み。着手は別段階）
- **不変**: ゲームロジック・画面遷移・状態管理・内部キー
- **証明**: `diff -r --exclude=.git --exclude=node_modules --exclude=pop . pop` に
  `engine/` `protocol/` `server/` が出てきたら約束を破っている

## 7. 賭けの扱い（2026-09-07・ユーザー指示「安全策で置き換え」）

**方針は決まった。安全側に倒す。** ただし「いちばん安全」な手（画面ごと外す・
倍率を廃する）は条件5（ゲームロジック・画面遷移・状態管理・内部キーは変更しない）を
破るので、**今回できるところまで**と**約束を緩めないと着手できないところ**を
はっきり分ける。この節が Hermes への指示になる。

### 7-1. いま実施する安全策（条件5を破らない範囲・全部やる）

金銭の比喩を**言葉と絵から完全に外す**。数と流れは1つも触らない。

| B | **カジノチップの意匠をやめる** | `ChipStack.tsx` と `.chipStack*` | 積み上がった円盤は賭博の記号そのもの |
| C | **`ALL IN` を使わない** | App.tsx:773 | ポーカーの賭け語。**`TODA A LUZ` も採らない**（全額賭けの含意が残る）。→ 下の 7-1-2 |

#### 7-1-2. 支度（旧・賭け金選択）の見せ方

`WAGERS` の**値も選択肢の数も画面遷移も変えない**。ラベルだけ替える。

| 現行 | 意味 | ポップ版のラベル |
|---|---|---|
| 少額の賭け | 小さく賭ける | **ちかい星まで**（みじかい旅） |
| 中額の賭け | 中くらい | **とおい星まで** |
| `ALL IN` | 全額 | **空のはてまで**（`ATÉ O FIM DO CÉU`） |

賭け額ではなく**旅の距離を選んでいる**ように読める語にする。
出すひかりの量が距離に応じて増えるのは同じだが、
「賭ける」ではなく「支度する」という言い方に統一する。

#### 7-1-3. 補充（旧・借金）

ひかりが尽きたとき、`LOAN_AMOUNT` を渡す流れは残る（画面遷移を変えないため）。
ただし**貸し借りではなく、時間で戻る灯りとして見せる**。

- `PEGAR EMPRESTADO` → `NOVA LUZ`
- ja: 「ひかりが尽きた。観測所が新しいひかりを分けてくれる。」
  「また灯せば、旅はいつでも続けられる。」
- **返済・取り立て・利息を思わせる語を1つも置かない**

### 7-2. 約束を緩めないと着手できない、より安全な手（今回はやらない）

人間が条件5の緩和を明示したときだけ、別の承認・別のブランチで行う。

1. **支度・みのりの画面を外す**（`"BETTING"` 局面ごと削る）… 画面遷移の変更
2. **倍率を廃し、残ったほしが次局へ持ち越される形にする** … `engine/match.ts` の変更

どちらも「資源を出して、結果しだいで戻りが変わる」ループ自体を消せるので、
7-1 より確実に安全。**Hermes は勝手に着手しない。**

### 7-3. IARC・データセーフティ（見た目を理由に虚偽申告しない）

7-1 を全部やっても、**遊びの構造は変わらない**。

- ひかりを出して一戦を始め、勝てば増えて戻り、負ければ戻らない
- 戻る量は残りほし数・連勝・コリンガ使用で変わる（内部では 2.0〜5.7 倍）

したがって IARC の「シミュレートされたギャンブル」に関する設問には、
**色と語を替えたことを理由に「該当しない」と答えてはならない。**
実装事実（`engine/match.ts` の配当計算が残っていること）に基づいて答える。
7-2 を実施したときだけ、答えが変わりうる。

データセーフティは実装事実どおりに申告する（棚卸し §8）:
- 収集・送信するのは**オンライン対局時の呼び名の文字列と再接続トークンのみ**
- 分析 SDK・広告 SDK・課金は**無い**（`fetch` 0件）
- 端末内に残るのは `localStorage` 5キー（言語・音・速さ・ひかり・ルール既読）

### 7-4. 人間の判断が要るもの（決定待ち一覧）

**リスキンの着手を止めているのは D1・D2 の2件だけ。** D3 以降は
アプリ化・ストア提出の段階で要るもので、リスキンと並行して決めればよい。

#### D1. CSS 変数名を替えるか — **リスキンを止めている**
`--felt`（カジノ卓のラシャ）`--blood`（血）`--gold` は、名前自体が世界観を
運んでいる。値だけ替えて名前を残すと、後で誰かが緑と赤に戻す。
- 推奨: **替える**（§2 の対応表）。ただし**値の変更とは別コミット**にして、
  機械的な改名だけの diff にする
- 替えない選択もある。diff は小さくなるが、名前と見た目がずれ続ける

#### D2. アプリと画面の表示名 — **リスキンを止めている**
`index.html` の `<title>` を commit 1〜4 で触るので、先に要る。
- 推奨: 画面 `PIF PAF — A TRAVESSIA` ／ ストア名 **「Pif Paf ほしめぐり」**
- `Pif Paf` は**遊びそのものの名前**なので残す。賭博語ではない

#### D3. 初回リリースにオンライン対戦を載せるか
- 推奨: **載せない（単機のみ）**。理由は3つ:
  1. Minimum Functionality は**オフラインで完結する単機**がいちばん強い説明になる
  2. データセーフティが「収集・送信なし」になり、プライバシーポリシーが1枚で済む
  3. Render 無料枠は15分で休止する。審査員が触った初回接続が失敗しうる
- オンラインは Web 版に残す。アプリへは後から足せる（`useOnlineGame` は
  そのままなので、入口を出すかどうかだけの話）

#### D4. Google Play のパッケージ名（**公開後に変更できない**）
- 推奨: `com.kongroo.pifpaf`
- テーマ語（`estrelas` / `hoshimeguri`）を入れると、将来テーマを替えたときに
  名前だけが取り残される。**遊びの名前で取るほうが長持ちする**

#### D5. プライバシーポリシーの掲載先（Play は必須）
- 推奨: GitHub Pages に1枚置く（`https://kongroo-gh.github.io/pifpaf/privacy.html`）
- D3 が「単機のみ」なら中身は「収集も送信もしない。端末内に設定を5つ保存するだけ」
- **ページを追加すると `.github/workflows` の配信対象に関わる**ので D9 と併せて

#### D6. 対象年齢層と IARC の答え方
- **子ども向け（Families）にはしない。** 子ども向けカテゴリはシミュレートされた
  ギャンブルを禁じており、§7-1 をやっても構造が残る以上、出せない
- 推奨: 13歳以上。IARC には実装事実どおり答え、**付いたレーティングを受け入れる**

#### D7. レーティングが受け入れられなかったときどうするか
先に決めておくと手戻りが小さい。
- 推奨: そのときは **§7-2 へ進む**（支度・みのりの画面を外す／倍率を廃す）と
  決めておき、条件5の緩和を**そのとき文書で明示する**
- いま §7-2 をやってしまう選択もあるが、遊びが別物になるので推奨しない

#### D8. 依存の追加（Capacitor 一式・書体の自前化）
AGENTS.md により**追加前に人間の確認が必須**。
- 推奨: リスキンが終わってから、**入れるパッケージの一覧を出したうえで**承認を取る

#### D9. `pop/` を配信に繋ぐか（CI）
`.github/workflows/` を触るので**変更前に人間の確認が必須**。
- 推奨: **当面繋がない**。`pop/` は単体で動く（`cd pop && npm install &&
  npm run dev --workspace=web`）ので、スクリーンショットも開発も困らない

#### D10. 現行版（ノワール版）を今後どうするか
- 推奨: **当面は併存**。ストアを通ったあとで「`pop/` を本体にするか」を別途決める
- いま決める必要はないが、決めないままだと2つを永久に手入れし続けることになる
